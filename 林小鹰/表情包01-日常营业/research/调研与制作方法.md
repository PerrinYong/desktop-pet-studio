# 林小鹰：微信表情调研与制作方法

调研日期：2026-11-24。目标：让用户在真实聊天里愿意发送的一套角色表情，而不只是 16 张可爱的立绘。

## 结论与证据边界

优先满足高频回应、软化语气、表达尴尬和轻度自嘲；保持形象统一，用明显不同的姿态区分含义，配简短口语。这是依据下列案例和设计复盘形成的创作判断，并非对这套作品传播效果的预测。

没有获得微信 2026 年全平台实时表情排行榜，也没有本系列上线后的发送、收藏或复用数据。以下流行案例均标明资料年代，不能将历史发送量解释为当前排名；QQ 的设计研究也不能直接当作微信用户统计。

## 受欢迎特征如何落到图上

1. **能代替一句回复。** 每张都对应一个明确的聊天意图。把“收到”和“安排”分开：一个是确认接收，一个是主动承接。
2. **情绪不是只有开心和难过。** “我想想”的犹豫、“让我缓缓”的耗尽、“啊？”的疑惑，与“我裂开了”的夸张震惊形成差别。
3. **反差来自角色。** 沉稳的小鹰也会戴墨镜、躺平、溜走。脸部圆盘、灰白配色、琥珀色眼睛与黏土材质保持一致。
4. **在小图里读得懂。** 单角色、少道具、主体大、短文案；文字采用深色粗字和白色外轮廓。导出后再看 120 和 240 像素，不只看高清图。
5. **语气有温度。** 感谢、拥抱、鼓励和慰劳占一定比例；夸张负面情绪主要表达自己的状态。
6. **组合有覆盖面。** 16 枚分为礼貌回应、情感支持、思考困惑、疲惫吐槽、结束聊天几个用途；避免只是同一张立绘换文字。

以上六条是本次设计推断，不是官方算法规则，也不保证作品成为热门。

## 制作流程

### 1. 锁定角色与语义

使用已有桌宠 canonical-base.png 作为唯一身份参考，复制到 references/character-original.png。保持灰色外壳、奶油白面盘和腹部、琥珀色眼睛、赭黄喙脚、两个耳簇和黏土触感。名字改为「林小鹰」，形象仍沿用原有的小猫头鹰。

每个表情先定义短句、动作、眼神和聊天触发场景，见 ../pack.json。每张单独生成，避免把多宫格裁开后出现角色大小、画质和文案不一致。完整提示词保存在 ../prompts/。

### 2. 生成与审图

使用 imagegen 内置图像生成，以同一角色图片作参考，直接要求透明背景、独立角色和准确的中文文案。先检查身份、表情含义、文字和肢体，再检查透明度与边缘；原图完整保存在 ../raw/。若出现错字或角色漂移，应回到图像生成工具定向修正，而不是在交付图上掩盖错误。

### 3. 导出与适配

scripts/export.ps1 使用 Windows System.Drawing 做等比缩放、透明留边和预览排版；不重绘角色或文字。输出 512×512 通用透明 PNG、240×240 小尺寸透明 PNG，以及一一对应的 120×120 缩略图。生成浅色/深色背景检查图，检查文字和白边在两种底色上的表现。

技术导出使用脚本，使尺寸、命名和清单可重复生成。图像创作由 imagegen 完成；技术导出与创作是两个阶段。每张记录尺寸、文件体积、透明像素比例和 SHA-256。

### 4. 静态与动态方法的选择

本次交付是完整的 16 枚静态系列。静态适合先验证聊天含义、文字和角色一致性。后续若做动态版，应为每个动作设计起势、主动作、停顿、回环的真正关键姿态，再按帧时长播放；避免只让整张静图来回晃动冒充角色动画。动态版需重新检查循环衔接、闪烁、透明边缘、时长与文件体积，并单独成套归档。

## 如何验证是否真的好用

这次只完成作品与技术验证。实际使用后可记录一周内哪些表情被主动发送、同一人是否重复使用、收到的人是否理解其含义，以及哪些短句需要解释。优先迭代使用频率低或语义重复的表情；不要仅以收藏或点赞当作聊天复用率。
