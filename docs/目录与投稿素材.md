# 目录与投稿素材

## 三个入口

| 要做什么 | 目录 | 内容 |
| --- | --- | --- |
| 直接用、找图 | 角色/表情包/成品 | 每套专辑里的静态、动态、配套素材；浏览.html 可并排查看 |
| 制作、改图 | 角色/表情包/专辑 | 原图、提示词、序列帧、pack.json、修订版 |
| 上传微信 | 角色/表情包/微信投稿/当前 | 主图、缩略图、含义词、封面、横幅、简介 |

角色层保留「角色设定／桌宠／表情包」。全局 docs 保存工程说明，tools 保存可复用脚本，艺术家资料保持独立。完整目录树见[工程首页](../README.md)。

## 一套专辑怎样摆放

成品中按「专辑 → 静态／动态／配套」分层。静态再按透明-240、纯白-240、透明-512、纯白-512、缩略图-120 分目录；动态保存 240 GIF。相同表情在各目录使用相同编号与文案。原为静态的专辑不创建空的动态目录。

本次 50 张动图各选一张高清原帧，生成透明与纯白静态表情；纯色背景固定为 #FFFFFF。240 用于聊天与平台素材，512 便于复用，120 用于缩略图。现有 104 张静态也一并整理，因此全库为 154 张静态、50 张动图。「羊毛失控」的 2 张附赠版本用「附赠-」前缀，避免与原静态图混淆。

「清单.json」记录每张的来源、哈希、含义词、格式及选帧理由。每套的总览提供深底与白底检查；浏览.html 不依赖网络或服务。

## 如何维护

1. 修改原图、动作、文案：在「专辑」中制作新修订；投稿.json 的 source_dir 指向当前版本。
2. 挑静态姿势：修改「静帧选择.json」。索引 0～3 对应 source-0.png～source-3.png，记录选择理由和原帧 SHA256。原帧变化会要求重新核对。
3. 生成「成品」，再生成「微信投稿/当前」。生成器拒绝覆盖已有输出；更新时先输出到新目录，检查后再切换入口与归档旧版。
4. 原图、修订、标准导出、选帧配置、脚本纳入 Git；成品和平台字段包可重建，避免多份手工维护。

在仓库根目录执行：

```powershell
python -m pip install -r tools/requirements.txt
python tools/build_sticker_library.py 林小羊
python tools/build_wechat_upload.py 林小羊
python tools/build_sticker_library.py 林小鹰
python tools/build_wechat_upload.py 林小鹰
```

成品导出需 Windows、PowerShell 7。Python 负责整理与验证，System.Drawing 从原帧裁切、等比缩放、合成白底，不重新绘制角色，也不从低清 GIF 放大。GIF 保持原文件字节不变。本次静态图按单帧边界适配画布，减少动作范围带来的空白。

只验证已生成素材：`python tools/build_sticker_library.py 林小羊 --validate-only`。自定义目录分别使用 --output-dir；投稿脚本可用 --library-dir 指向对应成品库。

## 微信目录

动态专辑的「主图」保持 GIF，「静态备选」单独提供透明 PNG、纯白 PNG、缩略图和上传顺序；按一种类型选择使用。附赠表情仍单列，不混入主专辑。账号资料与专辑资料分别集中。

旧「素材」「素材-图文融合版」「素材-图文融合完整版」已移到「微信投稿/历史」，迁移前后逐文件哈希一致，见[归档记录](投稿导出归档记录.json)。本次没有移动制作源文件或桌宠归档。
